# SMARTBUKATSU 通報・相談対応手順

対象管理番号: SB-20260819-012

## 1. 目的

アプリ内の通報・相談を安全に受け付け、問題確認、被害防止、再発防止、規約対応および必要な法令対応を行うための運用手順です。

## 2. 保管場所とアクセス

- 受付データは Cloud Firestore の `supportCases` コレクションへ保存します。
- 通報時点および通報後の対象投稿・返信・日報コメントの証拠は、各案件の `evidence` サブコレクションへ保存します。
- モバイルアプリには案件一覧や証拠の読み取り機能を実装しません。
- 閲覧・更新は、Firebase / Google Cloud プロジェクトで業務上必要な IAM 権限を付与された運営担当者だけが行います。
- 本番公開前に、デプロイ済み Firestore Security Rules で `supportCases` のクライアント読み書きが拒否されることを必ず確認します。

## 3. 受付経路

- 投稿、返信、共有振り返りの長押しメニューからのコンテンツ通報
- 投稿、返信の投稿者に対するユーザー通報
- 日報の「コーチとのやり取り」にあるコメント長押しからの内容・ユーザー通報
- 設定画面の「運営への相談窓口」からのバグ報告、改善要望、ハラスメント・規約違反相談

`mailto` は主受付経路にしません。Cloud Functions が認証、チーム所属、対象データを確認してから案件を作成します。

## 4. 案件状態

| 状態 | 意味 | 運営操作 |
| --- | --- | --- |
| `received` | 新規受付 | 内容と緊急性を確認する |
| `reviewing` | 確認中 | 必要な事実確認と安全措置を行う |
| `resolved` | 対応完了 | 判断理由と実施措置を記録する |

運営担当者は、受付を定期的に確認し、危険性が高い案件を優先してください。Apple / Google Play のUGC要件に沿って、問題コンテンツや利用者へ必要な措置を迅速に行います。

## 5. 証拠の取扱い

- 通報時点では、対象本文、投稿者UID、表示名、作成・更新時刻、削除状態、対象返信、添付情報を必要な範囲で保存します。
- 日報コメントの通報では、対象コメント、会話部分、日報ID、作成者、日付だけを保存し、体調、痛み、処置、振り返り本文など日報本体の情報は証拠へ複製しません。
- 通報後は、本文、対象返信、添付情報、削除状態など証拠に関係する変更だけを追跡します。
- 既読、リアクション等の調査に不要な更新は証拠履歴へ保存しません。
- 証拠を通常画面へ戻したり、広告・分析・通常サービス提供へ転用したりしません。
- 第三者提供は、本人同意、生命・身体・財産の保護、法令に基づく要請など、プライバシーポリシーで定めた場合に限定します。

## 6. 対応と記録

案件を確認した担当者は、少なくとも次を案件へ記録します。

- `status`
- 対応担当者を識別できる運営上の記録
- 確認内容と判断理由
- 非表示、削除、利用制限、関係者連絡等の実施措置
- 法的手続が継続する場合の `legalHold`

チーム管理者へ情報を共有する場合も、通報者や被害者の情報を必要以上に開示しないでください。

## 7. 保存期間と削除

- `status` が `resolved` へ変更された時点を案件対応終了とします。
- Cloud Functions が終了時刻と削除予定日時（終了から365日後）を設定します。
- 毎日実行する削除Functionが期限経過案件と証拠サブコレクションを削除します。
- `legalHold` が `true` の案件は自動削除しません。
- 法的手続が終了したら `legalHold` を解除し、残りの保存期間と削除予定日時を確認します。
- アカウント削除時、バグ報告・改善要望は削除し、安全通報・ハラスメント相談だけを上記の保全方針に従って保持します。

## 8. 公開前チェック

- `submitSafetyReport` と `submitSupportRequest` がデプロイ済みであること
- 投稿・返信の証拠追跡 `trackReportedWorkspacePostChanges` と日報コメントの証拠追跡 `trackReportedDailyReportChanges` がデプロイ済みであること
- 保存期限設定、自動削除Functionがデプロイ済みであること
- Firestore Security Rulesでモバイル利用者が `supportCases` を直接読み書きできないこと
- 運営担当者と確認頻度が決まっていること
- App Store / Google Playのプライバシー・Data safety回答が実装内容と一致すること
- SB-20260824-002の投稿フィルタ、ユーザーブロック、管理者非表示機能が公開前に完了していること
