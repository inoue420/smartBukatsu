## 確定した仕様

- 監督（owner/admin）・スタッフが、部員管理の保護者の行にある「子供」から紐づけを設定・解除する。
- 子供の候補は同じチームの一般部員・キャプテン・スタッフ。複数選択できる。
- クローズ後の追加仕様により、監督・スタッフが名前を手入力した未登録の子供も設定できる。部員一覧・人数・アカウントには追加しない。

- 保護者のカレンダーに「不参加連絡」を表示する。複数の子供がいる場合は1人を選択し、1人だけなら自動選択する。
- 欠席対象の子供と連絡を登録した人を分けて保存し、一覧に代理登録者を表示する。
- 子供本人と、その子供に現在紐づいている保護者全員が取り消せる。これはユーザー回答で確定した。
- 新版のFunctions経路では予定・日付・子供ごとに重複登録を防ぐ。修正は取り消して再登録する。旧版の本人連絡は後述の互換経路で維持する。
- 受付期限・詳細公開設定を引き継ぐ。受付終了後も既存連絡を取り消せる。オフライン送信・取り消しは従来どおり不可。
- 日誌・メディカル・動画等の閲覧権限は親子設定で追加しない。

## 実装と互換性

親子情報は`teams/{teamId}/members/{guardianUid}`の`childUids`と`childMemberships`へ保存する。
`childMemberships`は子供のメンバー文書の作成時刻を記録する。同じUIDで退団・再参加しても、古い紐づけは権限として使えない。
管理者が改めて設定した新しい紐づけは、遅れて届いた古い退団イベントで削除しない。

欠席は従来の予定文書の`absenceComments`を使用する。`uid`と`user`が欠席対象、`submittedBy: { uid, user }`が登録者となる。
旧形式の本人連絡も表示・重複確認・取り消しに対応する。名前だけからUIDを推測したり、既存データを一括移行したりしない。
同時送信・取り消しはサーバートランザクションで実行する。
通常の予定編集ではサーバー上の最新連絡を保持し、複数日予定から1日を分割する際は連絡の移動と元予定の更新を同じトランザクションで行う。

サーバーでは現在の所属・役割・親子関係・メンバー文書の世代・予定日・受付期限を確認する。
受付期限はJST基準で、0日前の場合は日別の開始時刻、終日予定は午前0時を使う。
クライアントでも日別開始時刻を参照する。画面を開いた後の期限切れはサーバー側で拒否する。
画面操作中のチーム・アカウント・役割変更や画面離脱後の結果は、新しい画面の状態へ反映しない。

過去の代理連絡があるチームを`users/{uid}/guardianAbsenceTeams/{teamId}`へサーバー専用で記録する。
アカウント削除では退団済みチームも対象にし、親子情報の配列・UIDキー・欠席対象・登録者を除去または匿名化する。
メンバー削除で代理操作を止めてから最終匿名化を行う。メンバー変更トリガーも無効になった紐づけを整理する。
