## 実装内容

- スタンプ件数のタップで、スタッフ（owner・admin・staff）または投稿者本人に送信者一覧を表示する。投稿者は名前ではなくUIDで判定する。
- 一般部員・保護者・主将は自分の投稿だけ確認できる。チーム所属と投稿の公開対象もサーバーで確認する。
- 通常一覧、展開した投稿、ピン留めした投稿から確認できる。送信操作は「＋」から行う。送信済みは「✓」で表示する。
- 1投稿につき1人1スタンプを維持する。同時送信・別端末の重複をトランザクションで防ぐ。
- 名前は既に読み込んでいる名簿をUIDで照合する。送信者ごとのユーザー文書取得は追加しない。照合できない人は「退会済み・名称未設定」と表示する。
- オフライン、権限変更、投稿削除・非表示、チーム・アカウント・チャンネル切替では一覧を閉じ、遅延した結果を表示しない。
- 取得失敗は再試行できる。閉じた一覧や別チームへ古い取得結果を反映しない。連打による同一の取得・送信も抑止する。
- 件数は既存の投稿購読で受け取る。送信結果と購読結果で二重に加算しない。一覧を開いた時点の件数を保持し、後から届いた件数更新を送信者不明として誤表示しない。

## 保存先と権限

| 保存先 | 内容・アクセス |
| --- | --- |
| `teams/{teamId}/workspacePosts/{postId}` | `reactions`には件数だけを保存。新形式では送信者UID一覧を保存しない |
| `teams/{teamId}/workspacePostReactionDetails/{postId}` | 投稿者UID、UID→スタンプの対応。スタッフ・投稿者のみget可能。list・クライアント書込は禁止 |
| `users/{uid}/workspaceReactionReceipts/{encodedTeamId}:{encodedPostId}` | 本人が送信したスタンプだけ。本人のgetのみ可能。list・クライアント書込は禁止 |
| `users/{uid}/workspaceReactionTeams/{teamId}` | 退会済みチームもアカウント削除時に見つける索引。サーバー専用 |

新規投稿の投稿者UIDはログインUIDと一致させ、件数は空から作成する。投稿者UID・件数・旧UID一覧・移行フラグのクライアント変更を禁止する。
送信者情報が残る投稿IDでの再作成も禁止する。名前の一致、投稿者の書き換え、別の人の送信済み文書の取得で閲覧権限を得ることはできない。
送信は`sendWorkspaceReaction` Callableで所属・投稿・公開対象・スタンプを検証して保存する。既存の送信APIもこのCallableに統一した。

アカウント削除では、新しい索引を対象チームの検索に加え、所属解除後に送信者UID・本人の送信済み文書・投稿者UIDを消す。
所属解除前に読み始めた送信トランザクションも、所属文書の削除により再試行または拒否される。匿名化後の新しい送信で旧投稿者の索引を再作成しない。
過去の件数は保持し、消した送信者情報を名前から復元しない。
