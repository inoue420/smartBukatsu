- 数値等の旧createdAtは従来の履歴検索へ回す。通常アプリ保存のserverTimestampは直接更新し、Timestampのナノ秒と文書ID降順で同時刻を安定させる。

退団・退会の後に旧参照から本人集計を作成することは、存在確認・除外UID・世代照合で防ぐ。

App.js、historyDataService.jsの固定購読先、schemaVersion 1、Android/iOSの名簿表示を維持する。

### 実機評価手順

005の読み込み最適化を含む現行アプリを使用し、Android/iOSで完全終了→再起動→対象チームを選択する。
管理者・選手のテストアカウントで、ホームの未読・体調件数と名簿の最新体調を基準として記録する。

| 操作 | 期待結果 |
| --- | --- |
| お知らせ1件を作成し、別の選手アカウントで確認済みにする | 未読数が増え、確認後に元へ戻る |
| 投稿でメンション・返信を付けて確認する | 対象者の通知件数が増減し、二重計上されない |
| 表示安定後にスタンプだけを追加／解除する | スタンプ表示が反映され、通知・体調件数は変わらない |
| 選手として通常コメント、添付追加／削除だけを行う | 日報の表示は更新され、名簿体調・体調集計は変わらない |
| 未確認の不調日報にスタッフコメントする | 確認済みになり未確認体調件数が減る。名簿の体調値は保持される |
| 新しい日報を作成し、疲労・睡眠・痛みを編集する | 名簿の最新体調・詳細に反映される |
| 過去の日報を編集する／最新日報を削除する | 過去編集では名簿が切り替わらず、最新削除では残った前の日報へ戻る |
| 担当・名前・チャンネル・ブロックを変更する | 再準備完了後、設定された対象範囲・表示へ一致する |
| チームA→B→Aと切替し、再ログインする | 別チームのデータ・件数が混ざらない |

問題報告はOS、操作、変更前後の件数、発生時刻を添える。個人情報・認証情報を含めない。
停止／再有効化、期限切れ添付、退会・重複・遅延イベントは必要に応じてサーバー側と組み合わせて追加確認する。
退会を確認する場合は使い捨てのテストアカウントを使用する。

本番で問題が出た場合は、対象チームの最適化を無効化して従来取得へ戻すことを最初の停止手段とする。自動で元履歴や索引を削除しない。
