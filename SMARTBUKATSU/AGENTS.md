# AGENTS.md

## 1. このファイルの目的

このリポジトリでCodexを使用する際の作業ルールを定めます。

Codexは、VS Codeで開いているローカルワークスペース内のファイルを確認・調査できます。
ただし、**ファイルの変更、作成、削除、コマンドによる変更、Git操作など、プロジェクトへ影響する操作は、必ず事前にユーザーの承認を得てください。**

承認を得るまでは、調査、分析、説明、変更案の提示だけを行ってください。

---

## 2. プロジェクト概要

- プロジェクト名：SMARTBUKATSU
- 開発環境：VS Code
- フレームワーク：Expo / React Native
- ビルド・配布：EAS
- 対応OS：Android / iOS
- バックエンド：Firebase
- ソース管理：Git / GitHub
- 開発体制：オーナー、バイト生、Codexによる共同開発
- GitHubではPull Requestを使用する

---

## 3. 最重要ルール

### 3.1 変更前の承認は必須

以下の操作は、どれだけ小さな変更でも、実行前に必ずユーザーの承認を得てください。

- 既存ファイルの編集
- 新規ファイルの作成
- ファイル名の変更
- ファイルやフォルダの移動
- ファイルやフォルダの削除
- パッケージの追加、更新、削除
- 設定ファイルの変更
- 自動整形による変更
- コード生成
- Gitのcommit、revert、reset、stash
- ブランチの作成、変更、削除
- GitHubへのpush
- Pull Requestの作成、更新、マージ
- EAS、Expo、Firebaseなどの外部サービスに影響する操作
- データベース、認証、ストレージ、セキュリティルールの変更
- シェルコマンドやスクリプトによるファイル変更

変更が必要な場合は、実行前に次の内容を提示してください。

1. 変更の目的
2. 変更予定のファイル
3. 変更内容の要約
4. 想定される影響
5. 元に戻す方法
6. 実行予定のコマンド
7. ユーザーの承認待ちであること

承認を得るまでは変更を実行しないでください。

### 3.2 調査は許可

次の操作は、プロジェクトを変更しない範囲で実行できます。

- ワークスペース内のファイル閲覧
- コード検索
- Gitの状態確認
- Gitの差分確認
- Gitの履歴確認
- 設定内容の確認
- エラーログの分析
- コード構成の説明
- 変更案の提示
- 問題箇所の特定
- 実行すべきコマンドの提案

ただし、閲覧コマンドであっても、外部サービスへのアクセスや認証を伴う場合は事前確認してください。

---

## 4. 作業開始時の確認

作業開始時は、可能な範囲で次を確認してください。

- 現在のGitブランチ
- `git status`
- 未commitの変更
- 未追跡ファイル
- ユーザーや他の開発者による作業途中の変更
- 対象機能に関係するファイル
- Expo SDK、React Native、主要パッケージの現在のバージョン

既存の未commit変更がある場合は、それを上書き、削除、整形、移動しないでください。

自分が作成したものではない変更を発見した場合は、その内容をユーザーへ報告し、扱いについて確認してください。

---

## 5. 変更方針

承認後に変更する場合も、次のルールを守ってください。

### 5.1 必要最小限の変更

- 指示された目的に必要な範囲だけを変更する
- 関係のないリファクタリングを行わない
- 関係のない命名変更を行わない
- 関係のない整形を行わない
- 大量のファイルを一括変更しない
- 既存仕様を推測だけで変更しない
- AndroidとiOSの両方への影響を確認する
- Firebaseの既存データ構造との互換性を考慮する

### 5.2 段階的に変更する

大きな変更は一度に行わず、次のように分割してください。

1. 現状調査
2. 変更案の提示
3. ユーザー承認
4. 最小単位の変更
5. 差分確認
6. テスト
7. 結果報告
8. 次の変更について再承認

一度の承認を、関連の薄い追加変更への包括的な許可として扱わないでください。

### 5.3 不明点は勝手に補完しない

仕様が不明確な場合は、実装を進めずに次を示してください。

- 不明点
- 考えられる選択肢
- 各選択肢のメリットとデメリット
- 推奨案

## 6. Git運用

### 6.1 ブランチ

- `main`へ直接commitしない
- `main`へ直接pushしない
- `develop`へ直接commitしない
- `develop`へ直接pushしない
- 作業ごとに専用のfeatureブランチを使用する
- バイト生、オーナー、Codexで同じ作業ブランチを同時に使用しない

Codex用ブランチの例：

```text
feature/codex-login-improvement
feature/codex-team-switching
fix/codex-android-build-error
```

ブランチ作成も事前承認を得てください。

### 6.2 commit

commitはユーザーの明示的な承認がある場合だけ実行してください。

commit前には次を提示してください。

- 変更ファイル一覧
- `git diff`の要約
- テスト結果
- commitメッセージ案

1つのcommitには、原則として1つの目的だけを含めてください。

### 6.3 push・Pull Request

次の操作はユーザーの明示的な承認なしに行わないでください。

- `git push`
- force push
- Pull Request作成
- Pull Request更新
- Pull Requestのマージ
- GitHub上のIssueや設定変更

Codexは原則として、ローカルでの変更と検証までを担当します。

### 6.4 禁止するGit操作

次の操作は、ユーザーから具体的な指示がない限り実行しないでください。

```text
git reset --hard
git clean -fd
git clean -fdx
git push --force
git push --force-with-lease
git rebase
git filter-branch
git filter-repo
```

変更を戻す必要がある場合は、まず安全な方法を説明してください。

## 7. Expo・EAS運用

### 7.1 勝手に変更しない項目

次の項目は、明示的な承認なしに変更しないでください。

- Expo SDKのバージョン
- React Nativeのバージョン
- `app.json`
- `app.config.js`
- `eas.json`
- Android package名
- iOS bundle identifier
- version
- buildNumber
- versionCode
- scheme
- plugins
- permissions
- entitlements
- deep link設定
- AdMob関連設定

### 7.2 実行前承認が必要なコマンド

次のコマンドは、実行前に必ず承認を得てください。

```text
npm install
npm uninstall
npm update
npx expo install
npx expo prebuild
npx expo run:android
npx expo run:ios
eas build
eas submit
eas update
eas credentials
```

`package.json`やロックファイルを変更する可能性があるコマンドは、すべて変更操作として扱ってください。

### 7.3 本番操作は禁止

ユーザーからその操作を明示的に依頼されない限り、次を実行しないでください。

- productionビルド
- App Store Connectへの提出
- Google Play Consoleへの提出
- OTAアップデート配信
- 本番バージョン番号の更新
- 証明書や署名情報の更新

---

## 8. Firebase運用

次の操作は、明示的な承認なしに実行しないでください。

- Firebaseへのdeploy
- Firestoreデータの追加、更新、削除
- Authenticationユーザーの変更
- Storage内ファイルの変更
- Cloud Functionsのdeploy
- Firestore Rulesの変更
- Storage Rulesの変更
- Firebase Hostingのdeploy
- インデックスの作成や削除
- 本番環境への接続設定変更

特に、次のコマンドは勝手に実行しないでください。

```text
firebase deploy
firebase use
firebase functions:delete
firebase firestore:delete
```

セキュリティルールを変更する場合は、変更前後の差分、影響範囲、想定ユースケースを提示してください。

## 9. 秘密情報・認証情報

次の情報を表示、記録、変更、commit、pushしないでください。

- `.env`
- `.env.local`
- `.env.production`
- APIキー
- サービスアカウント鍵
- Firebase Admin SDK秘密鍵
- Appleの`.p8`ファイル
- Android keystore
- keystoreのパスワード
- EASアクセストークン
- GitHubトークン
- Google Playサービスアカウント鍵
- 決済サービスの秘密鍵
- 個人情報
- 本番ユーザーデータ

秘密情報を発見した場合は、値を出力せず、ファイル名と問題の種類だけをユーザーへ報告してください。

秘密情報をログ、コメント、テストコード、サンプルコードへ書かないでください。

---

## 10. パッケージ管理

パッケージの追加、更新、削除は、必ず事前承認を得てください。

提案時は次を説明してください。

- パッケージ名
- 導入理由
- 現在のExpo SDKとの互換性
- Androidへの影響
- iOSへの影響
- ネイティブビルドが必要か
- Expo Goで動作するか
- dev-clientが必要か
- EAS再ビルドが必要か
- 代替手段
- ライセンスや保守状況

主要パッケージを、問題解決と関係なく一括更新しないでください。

---

## 11. テストと検証

テストコマンドも、ファイルや設定を変更する可能性がある場合は事前承認を得てください。

承認後、変更内容に応じて可能な範囲で次を確認してください。

```text
npx expo-doctor
npx tsc --noEmit
npm test
npm run lint
npx expo export --platform android
npx expo export --platform ios
```

ただし、実際のプロジェクトに存在しないスクリプトを勝手に追加しないでください。

テスト失敗時は、失敗を隠さず次を報告してください。

- 実行したコマンド
- 成功または失敗
- エラー内容の要約
- 原因の推定
- 今回の変更が原因か
- 未解決事項

---

## 12. 作業完了時の報告

変更を実施した場合は、最後に次を報告してください。

1. 変更したファイル
2. ファイルごとの変更内容
3. 変更していない重要ファイル
4. 実行したコマンド
5. テスト結果
6. Androidへの影響
7. iOSへの影響
8. Firebaseへの影響
9. 既知の問題
10. 手動確認が必要な項目
11. 元に戻す方法
12. commit・push・PRが未実施かどうか

変更が承認されなかった場合は、ファイルを変更せず、提案内容だけを報告してください。

---

## 13. ユーザーへの承認依頼フォーマット

変更が必要な場合は、次の形式で承認を求めてください。

```text
【変更承認のお願い】

目的：
変更予定ファイル：
変更内容：
影響範囲：
実行予定コマンド：
元に戻す方法：
注意点：

上記の変更を実行してよいでしょうか。
承認をいただくまでは、ファイル変更やコマンド実行は行いません。
```

複数の変更がある場合は、可能な限り分けて承認を求めてください。

---

## 14. このルールの優先順位

この`AGENTS.md`のルールは、このリポジトリ内でのCodex作業に適用します。

特に次の原則を最優先とします。

1. 変更前に必ず承認を得る
2. 承認前は読み取り・調査だけに留める
3. 必要最小限の変更にする
4. `main`と`develop`を直接変更しない
5. push、PR、マージ、本番公開は勝手に行わない
6. 秘密情報を扱わない
7. 問題があれば安全に戻せる状態を保つ
